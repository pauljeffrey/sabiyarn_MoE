# AfriCOMET reward model -- a SEPARATE environment, never installed next to the root requirements.txt.
#
# `unbabel-comet` pins transformers<5, huggingface_hub<1 and numpy<2. The SabiYarn model code is written
# against transformers 5.x (root requirements.txt pins 5.14.1), so the two cannot share one environment:
# installing comet next to it silently downgrades transformers and breaks the model class.
#
# Instead, comet lives in its own virtualenv and is driven over a pipe by rl/comet_worker.py; the trainer
# stays on transformers 5. Point `reward_python` (or RL_REWARD_PYTHON / AFRICOMET_PYTHON) at that venv's
# python and nothing else changes.
#
#   # --system-site-packages reuses the torch already installed in the main environment (~2.5 GB saved);
#   # the pins below are installed INTO the venv and shadow the outer transformers/numpy for this process only.
#   python -m venv --system-site-packages .venv-comet
#   .venv-comet/bin/pip install -r rlhf/requirements.txt
#
#   # then, for training:
#   python rlhf/scripts/run_rlhf.py reward_python=.venv-comet/bin/python
#   # and for evaluation:
#   AFRICOMET_PYTHON=.venv-comet/bin/python python -m eval_suite.run --model <ckpt> --africomet masakhane/africomet-stl
#
# On Modal this venv is baked into the image by rl/modal_rl.py (the `comet` image) -- nothing to do by hand.
# Verify a built venv with:  .venv-comet/bin/python -m rl.comet_worker --help
#
# If torch is NOT already present (a bare box with no main install), drop --system-site-packages and pip
# will pull its own CPU/CUDA torch build, which comet supports from 1.6 up.
